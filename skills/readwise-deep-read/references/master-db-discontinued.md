## Master-DB highlights — discontinued (2026-08-16)

**Do not call `readwise_create_highlights` (the classic Readwise v2 `/api/v2/highlights/` endpoint) as part of this pipeline.** Diagnosed 2026-08-16: Reader (v3, what this skill saves to) and classic Readwise highlights (v2) are two independent systems with no cross-linking. Every `readwise_create_highlights` call auto-creates a brand-new "book" in the v2 system, which the Readwise Official Obsidian plugin then syncs into `Resources/Readwise/Books/` as a **second, separate local file** for the same source — alongside the real Reader-document sync already living in `Articles`/`Podcasts`/`Snipd`/`Tweets`. That Books-folder duplicate is worse in every way: no `notes` field (so `mirror_notes.py` can't touch it and it never gets the Document Notes callout), a generic placeholder cover instead of the source's real image, and an empty `source` field. Since Obsidian Publish serves the whole `Resources` folder, **both pages go live** — readers can land on the ugly duplicate instead of the properly-formatted one.

Master-DB highlights were originally item 2 of this skill's Purpose (see git history / older revisions), redundant with Phase 2's Reader-native inline highlights, which already give visible, tagged, anchored highlights inside Reader (and sync cleanly to Obsidian as part of the one true document). Skip the master-DB step entirely — do not add it to subagent prompts, do not run it manually. If a future need arises for classic-Readwise highlights specifically (e.g. Readwise Daily Review integration), reconsider this decision explicitly rather than reintroducing it by habit.

A 2026-08-16 cleanup attempt tried to identify existing Books-folder duplicates by normalized-title matching against `Articles`/`Podcasts`/`Snipd`/`Tweets` siblings and deleted 78 files. **This was wrong and all 78 were restored the same day** — title matching (even normalized/fuzzy) is not proof of duplication; it deleted real, independently-read books ("Building a Second Brain," "The Cathedral & the Bazaar," etc.) whose titles happened to overlap an unrelated article's title. See the `readwise-books-folder-duplicate-fix` memory for the full incident and the restoration method (re-fetch from `/api/v2/export/?ids=<id>` — book records persist server-side, no delete endpoint exists). **Do not attempt duplicate cleanup by title matching again.** If revisited, match on exact `source_url` equality only, and present the match list for the user's review before deleting anything.
